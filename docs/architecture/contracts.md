# Contracts

Contracts the operator owns or depends on. Changing one updates its entry in the same PR.

### Chart value `operator.webhook.clusterIssuer`
**Owner:** `charts/nebari-llm-serving` (`values.yaml`, `templates/operator-webhook-cert.yaml`) · **Consumers:** every chart install, through the webhook serving Certificate's `issuerRef`; the docs site (`configuration.mdx`, `installation.md`, `quickstart.mdx`, `upgrading.mdx`) and `README.md` (verified: `rg -n "operator\.webhook\.clusterIssuer|\.Values\.operator\.webhook" --glob '!node_modules' --glob '!.worktrees' .`). The kind dev cluster installs from `dev/manifests/`, not the chart, and is unaffected.
**Promises:** A string naming a cert-manager `ClusterIssuer` (the `kind` stays `ClusterIssuer`). It signs the operator's admission webhook serving Certificate, whose DNS names are `<svc>.<ns>.svc` and `<svc>.<ns>.svc.cluster.local`. Default `nebari-ca-issuer`, which NIC creates in releases that include nebari-infrastructure-core#787; before this value existed the issuer was hardcoded to `selfsigned-issuer`. A missing key or `operator.webhook` block (for example values reused from an older release with `helm upgrade --reuse-values`) renders the default. An explicitly empty value fails the render with `operator.webhook.clusterIssuer is required: ...`. The chart does not create the issuer.
**Since:** 2026-11-20

### Endpoint status conditions (`ExternalEndpointReady`, `InternalEndpointReady`)
**Owner:** `operator/internal/controller` · **Consumers:** the docs site (`architecture.mdx`, `configuration.mdx`), unit and envtest tests in the same package, humans via `kubectl`; `PassthroughModelReconciler` and `LLMModelReconciler` call `endpointCondition`, which reads the endpoint's previous condition (status, reason, `lastTransitionTime`) back from the model (verified: `rg -l "EndpointReady|RouteNotAccepted|RoutePending|RouteStatusUnreadable" --glob '!node_modules' --glob '!.worktrees' .`). The `operator/test/e2e/e2e_test.go` hit is `verifyMetricsEndpointReady`, unrelated.
**Promises:** Applies to LLMModel and PassthroughModel. Status is `True`, `False` or `Unknown`. Reasons today are `Applied`, `EndpointDisabled`, `ApplyFailed` and `GatewayCRDUnavailable`. The reasons `RoutePending` (`Unknown`), `RouteNotAccepted` (`False`) and `RouteStatusUnreadable` (`Unknown`) are emitted by both reconcilers. For both kinds, `Applied` means the Gateway accepted the route, and `lastTransitionTime` comes from the reconciler's `Clock`. An LLMModel endpoint condition covers the route only; a PassthroughModel endpoint condition covers route and policy together. A disabled endpoint is `False/EndpointDisabled` and is not a failure. No program outside the operator parses the reasons.
**Since:** 2026-11-20 (issue #233)

### `status.phase` of LLMModel and PassthroughModel
**Owner:** `operator/internal/controller` · **Consumers:** `dev/run-dev.sh:85`, `dev/usage-e2e.sh:135,163`, `dev/test-model-scope.sh:131-132` (all `kubectl wait ... phase=Ready`), the docs site (verified: `rg -n "status\.phase" --glob '!node_modules' --glob '!.worktrees' --glob '!operator/**' --glob '!docs/**' --glob '!charts/**/crds/**' .`)
**Promises:** Same enum as today. An apply failure or `GatewayCRDUnavailable` downgrades LLMModel `Ready` to `Degraded` and gives PassthroughModel `Error`. `RouteNotAccepted` is treated the same way: it gives LLMModel `Degraded` and PassthroughModel `Error`, while `RoutePending` and `RouteStatusUnreadable` leave `Ready` untouched on both. The scripts' `wait ... phase=Ready` behave as before on a healthy cluster.
**Since:** 2026-11-20 (issue #233)

### Generated HTTPRoute
**Owner:** Envoy AI Gateway and Envoy Gateway (external) · **Consumers:** `removeEndpoint` (`passthroughmodel_endpoints.go:30`), `readRouteAcceptance` (`route_acceptance.go:86`) (verified: `rg -n '"HTTPRoute"' operator --glob '!*_test.go'`)
**Promises:** Same name and namespace as its AIGatewayRoute. `spec.parentRefs` and `spec.hostnames` are copied from the AIGatewayRoute (ai-gateway v1.1.0 `internal/controller/ai_gateway_route.go:368-370`). `status.parents[]` is written by Envoy Gateway, with the `Accepted` condition's `observedGeneration` set to the HTTPRoute generation. The `reconcilers/auth.go` hits are `targetRefs` the pack writes, not reads.
**Since:** 2026-11-20 (issue #233)

### AIGatewayRoute `status.conditions`
**Owner:** Envoy AI Gateway (external) · **Consumers:** `readRouteAcceptance`, via `aiGatewayNotAcceptedMessage` (`route_acceptance.go`), for the message only (verified: `rg -n "NotAccepted" operator --glob '!*_test.go'`)
**Promises:** At most one condition, of type `Accepted` (True) or `NotAccepted` (False), with no `observedGeneration`. The operator reads it only for its message, never to decide a status or reason (ai-gateway v1.1.0 `internal/controller/controller.go:551-566`, `api/v1beta1/status.go:13-16`). `readRouteAcceptance` is the only reader, through `aiGatewayNotAcceptedMessage`, which returns the message of the first `NotAccepted=False` or `Accepted=False` condition; the other hits are the reason constants in `conditions.go` and comments.
**Since:** 2026-11-20 (issue #233)

### `gatewayRequeue`, `hasGatewayFailure`, `phaseWithGatewayFailure`
**Owner:** `operator/internal/controller/conditions.go` · **Consumers:** `llmmodel_controller.go:232,245`, `conditions.go` itself, and the PassthroughModel requeue (`gatewayRequeue`, `passthroughmodel_controller.go:230`) (verified: `rg -n "gatewayRequeue\(|hasGatewayFailure\(|phaseWithGatewayFailure\(" operator --glob '!*_test.go'`)
**Promises:** Signatures are unchanged. `gatewayRequeue` returns the shortest interval any condition asks for, keyed on reason: `RoutePending` 5 s, `GatewayCRDUnavailable` 15 s, `RouteStatusUnreadable` 15 s, `RouteNotAccepted` 1 min, `ApplyFailed` 1 min, otherwise 0. It considers `Unknown` conditions as well as `False`, and ignores reasons it does not know (so `UpstreamCredentialResolved=Unknown/LookupFailed` contributes nothing). `hasGatewayFailure` is true for a `False` condition whose reason is `GatewayCRDUnavailable`, `ApplyFailed` or `RouteNotAccepted`; `RoutePending` and `RouteStatusUnreadable` requeue without counting as failures. `phaseWithGatewayFailure` is unchanged and picks up `RouteNotAccepted` through `hasGatewayFailure`. Existing inputs give existing outputs. While an LLMModel's `SecurityPoliciesReady` is pending, the LLMModel reconciler returns a flat 15 s (`gatewayCRDRequeue`, `llmmodel_controller.go:242-244`) before consulting `gatewayRequeue`, so a `RoutePending` endpoint is rechecked at 15 s then, not 5 s.
**Since:** 2026-11-20 (issue #233)

### `endpointCondition`, `readRouteAcceptance`, `routeAcceptanceCondition`
**Owner:** `operator/internal/controller/route_acceptance.go` · **Consumers:** `PassthroughModelReconciler` (`passthroughmodel_controller.go:157,173`) and `LLMModelReconciler` (`llmmodel_controller.go:216,223`) (verified: `rg -n "endpointCondition\(" operator --glob '!*_test.go'` finds the definition and those four calls)
**Promises:** Implemented and unit-tested in `operator/internal/controller/route_acceptance.go`; both reconcilers call `endpointCondition` for each enabled endpoint. `readRouteAcceptance` reads the generated HTTPRoute for the applied AIGatewayRoute, matches the `status.parents[]` entry on the route's single parent ref (`name`, `namespace`, `sectionName`), and counts it only when the HTTPRoute is current (same hostnames and parent refs, `Accepted.observedGeneration` equal to the HTTPRoute generation). A NotFound HTTPRoute is "route not found", not an error. `routeAcceptanceCondition` and `endpointCondition` turn that observation into the endpoint condition, using a 2 minute creation window and a 2 minute previous-condition window to choose between `RoutePending` and `RouteNotAccepted`, and stamp `lastTransitionTime` from the injected clock. A failed apply is reported as `ApplyFailed` and no acceptance read happens. A read error that is a NoMatch error gives `False`/`GatewayCRDUnavailable`. Any other read error gives `Unknown`/`RouteStatusUnreadable` with the message `reading HTTPRoute status: <err>`, unless the previous condition is `False`/`RouteNotAccepted`: then it stays `False`/`RouteNotAccepted` with `; last status read failed: <err>` appended once (a repeated error replaces that suffix, so the message does not grow).
**Since:** 2026-11-20 (issue #233)

### `LLMModelReconciler` and `PassthroughModelReconciler` struct fields
**Owner:** `operator/internal/controller` · **Consumers:** `operator/cmd/main.go` (constructs both reconcilers without `Clock`), `passthroughmodel_controller.go:145` and `llmmodel_controller.go:216,223` (read it through `realClockIfNil`), the controller tests (verified: `rg -n "Clock" operator --glob '!*_test.go'`)
**Promises:** `PassthroughModelReconciler` has `Clock clock.PassiveClock` (`k8s.io/utils/clock`). A nil `Clock` means the real clock (`realClockIfNil`), and `cmd/main.go` leaves it nil; tests inject a fake clock to step through the route-acceptance windows. `LLMModelReconciler` has the same field (`llmmodel_controller.go:66`) and also leaves it nil in `cmd/main.go`. `Client`, `Scheme` and `Config` are unchanged.
**Since:** 2026-11-20 (issue #233)
